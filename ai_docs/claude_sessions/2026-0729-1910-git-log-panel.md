# Session: Git log panel (JetBrains-style history browser)

Session ID: da453896-9129-406c-a277-4c0be1ac017c
Date: 2026-07-29

### Ask

> "Pls add a git log panel similar to JetBrains' git log (as in Goland).
> Please include the ability to view commit meta-data, changed files,
> and to cherry-pick, revert, and reset commits. Include any other
> low-hanging fruit."

Mid-session addendum: "In the UI make good use of icons and buttons."

### What shipped

A commit-history browser in the bottom strip, toggled with **Esc-L** or
≡ → Git → "Show git log". Two new files plus wiring:

- `internal/app/gitlog.go` — panel state, loaders, geometry, mouse,
  drawing (+ `gitlog_test.go`, 13 tests)
- `internal/app/gitlogactions.go` — the Actions ▾ verb surface
  (+ `gitlogactions_test.go`, 6 tests)

Layout mirrors the git changes panel deliberately (parallel structure,
not shared code — the house patterns are the shared part): commit list
left, detail right, header rule = height drag, list/detail divider =
width drag, wheel per pane, Esc-= / Esc-- resize.

**Commit list**: `git log --all` (so cherry-pick can reach other
branches), newest first, capped at 400 with a "400+" title when
truncated. Rows: `●` marker on ref-decorated commits, accent short
hash, subject, muted `author · age` tail when the column is ≥ 46 cols.
Selection preserved BY HASH across refreshes.

**Detail pane**: one async `git show --decorate --pretty=fuller --stat
--patch` — metadata (author + committer + both dates + decorations),
changed-file stat, and the full patch as a single colored scrollable
document. Results post `gitLogShowEvent`s; stale fetches drop against
the current selection (commits are immutable, so a matching hash is
never refetched).

**Header buttons** (all single-width glyphs through btnRects):
`Actions ▾`, `⧉ hash` (one-click full-hash copy), `⟳` (manual
refresh), `✕`.

**Actions ▾** (≡ "Git log actions" is the keyboard twin) opens the
palette picker: cherry-pick onto current branch, revert (`--no-edit`),
reset (soft/mixed/hard via a SECOND picker — only `--hard` confirms),
detached checkout, create branch/tag at the commit (prompt for name),
copy hash (full, via OSC 52), copy message (full body, one inline
fork). Labels name the branch and hash they'll touch. All writes go
through `runGitCmd`.

**Double-click a detail diff row** jumps the editor to that file/line:
`gitLogDetailTarget` generalizes `diffTargetLine` to a multi-file
patch (tracks the current `+++ b/` file and the new-side hunk
counter), paths resolve against the repo toplevel and are confined to
rootDir, line clamps if history moved on.

### Wiring (the checklist for the next panel)

- `app.go`: `gitLog gitLogState` field, `*gitLogShowEvent` dispatch,
  `editorRect` height subtraction, "gitlog"/"gitlogdiv" drag modes,
  press routing case, `scrollAt` branch, `drawGitLog()` call, two menu
  rows in the Git group, and `refreshGitStatus` now also calls
  `refreshGitLogCommits()` (no-op while collapsed) — so git commands
  and the 10s tick keep the log honest for free.
- `leader.go`: `Esc-L` (shifted — lowercase 'l' is too close to typing
  flow after a stray Esc).
- Single occupancy in every direction: opening the log evicts the
  changes panel + a bottom-docked terminal, and vice versa
  (`gitpanel.go`, `terminal.go` both close `gitLog`);
  `growBottomPanel`/`shrinkBottomPanel` fan out to all three.

### Decisions

- **No ASCII commit graph** — `--graph` interleaves connector rows
  with the format output and would complicate row hit-testing; clean
  follow-up if wanted.
- **No multi-select ticks** — commit verbs are single-target; the
  changes panel's checkbox pattern didn't carry over.
- Reset soft/mixed run without confirm (reflog-recoverable);
  cherry-pick/revert create commits, also no confirm. Only `--hard`
  gates.
- Subject is the LAST field in the `%x09`-separated log format so a
  tab inside a subject survives `SplitN`.
