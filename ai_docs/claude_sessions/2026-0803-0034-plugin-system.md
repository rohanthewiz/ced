# Session: A plugin system — declarative shell, not a host

Session ID: 0fefcbaf-e9fc-44da-82a4-76f1141424a5
Date: 2026-08-03

### Ask

> "Add a plugin system to ced"

Four words, and `CLAUDE.md` said no to them:

> **What NOT to add** — A config file / dotfile / plugin system. ced is
> opinionated.

So the session opened by naming that conflict rather than quietly
resolving it either way, and asking two questions: what SHAPE, and which
capabilities. The answers picked:

- **Grow `actions.json` into a declarative manifest** — shell-out only,
  no new runtime, no new dependency, still one static binary. (The
  alternatives offered were an ndjson JSON-RPC plugin host riding
  `lsp.StartNDJSON` like LSP/ACP/MCP, and an embedded pure-Go
  interpreter. Both were real options; both make ced a host.)
- **All four capabilities**: commands, buffer transforms, decorations,
  event hooks.

### The line, and where it moved to

The entry didn't get deleted — it got *sharpened*. What's still banned
is a **host** plugin system: `.so` loading (costs the static binary and
CGO), an embedded interpreter, or an editor API that has to stay stable
across releases. What landed instead is data:

> a ced plugin is a JSON manifest of SHELL COMMANDS the user already had
> permission to type — the editor's contribution is *when* to run one
> and where the output goes, not a runtime to run it in.

`CLAUDE.md` now carries the test a future field has to pass: it still
has to reduce to "a command line plus a place to put its output."
`input`/`output`/`on`/`glob` do. A callback into editor internals would
not. That sentence is the whole guardrail.

This is the same side of the line as themes (data from a fixed key list)
and skills (markdown ced hands off but never runs) — a third way of
being an exception, not a new precedent.

### It's actions.json one octave up

That's the frame worth keeping. `actions.json` answered *"give me a menu
row that shells out"*. Plugins answer the three things that row could
never do:

| | |
|---|---|
| `commands` | put a command's output **back in the buffer** |
| `hooks` | run **without being clicked** |
| `decorations` | **paint over the code** |

Prompt collection is imported wholesale from `customactions` — same
schema, same form modal, same env-var contract, `ValidatePrompts` merely
exported. One dialect to learn, not two. A user who has written one
`actions.json` entry already knows half of this.

### Location and shape

```
~/.config/ced/plugins/<name>/plugin.json
```

One directory per plugin, so a plugin can ship scripts beside its
manifest — `$PLUGIN_DIR` is what makes that work. Without it an author
has to hardcode an absolute path that breaks for everyone else.

Three optional sections. The smallest working manifest is a `commands`
array with one `{label, command}`; the name falls back to the directory.

### The output format was the load-bearing choice

Decorations parse the compiler/grep convention:

```
path:line:col: severity: message
path:line: message
line:col: message
line: message
```

That decision is *why the feature is worth having*. It means a useful
provider is a one-liner the user already knows how to write —
`grep -n TODO`, `go vet`, `shellcheck -f gcc`, `eslint -f unix`,
`golangci-lint --out-format=line-number` — instead of a JSON envelope
nobody's linter emits and everybody has to wrap. A format ced invented
would have made the feature theoretical.

The parser is **incremental, not a split on `:`**, because messages
routinely contain colons (a Go `:=`, a URL, "expected ':'"). Each field
is claimed only if it looks like what that position wants: the first is
a path unless it parses as an integer, the column only if the next field
is an integer. So `12:\tfoo := bar` from `grep -n` over Go source keeps
its `:=` — `"\tfoo "` isn't an integer, so the column slot goes
unclaimed and the whole remainder is the message.

Unparseable lines are **dropped, never reported**. Real tools interleave
summaries, progress, and blanks with their findings; treating those as
errors would mean every provider needs a `| grep` to stay quiet.

### Two concessions to how linters actually behave

Both discovered by asking "what would a user wire up first?" and the
answer being `go vet`:

- **Decorations read stdout AND stderr.** `go vet` and half the Go
  toolchain report findings on stderr. A provider that only read stdout
  would silently see nothing from the most obvious first thing to try.
- **Exit status is ignored** on that path. A linter exits non-zero
  precisely when it has something to say. This also makes
  "binary not installed" degrade for free — sh prints `command not
  found`, nothing parses, the provider contributes nothing. No
  special-casing.

The **command** path is the opposite and deliberately so: stdout and
stderr are captured **separately and never merged**. A formatter that
prints a deprecation warning to stderr must not have that warning
spliced into the user's source, which is exactly what one
`CombinedOutput` there would do.

### Writing back into a buffer

Everything the done-handler needs is captured **before** the goroutine
starts — path, `EditRev`, and the range it may overwrite. By the time
the command exits, the tab, the selection, and the cursor may all be
somewhere else, and a handler that re-derived any of it from live state
would write the output into whatever the user happened to be looking at.
A rev mismatch **discards** with a flash. Same staleness discipline as
the ghost text and the chat results.

Two details fell out of the editor's existing primitives rather than
needing new ones:

- **One undo step comes free.** `insertStringAt` already calls
  `deleteSelectionAt` (which pushes the structural entry) and then
  inserts without pushing a second. So `InsertString` over a selection
  *is* one entry, and a whole-file replace is `SelectAll` +
  `InsertString`.
- **A whole-file replace restores the view through `RestoreView`**, not
  `MoveCursorTo` — the primitive the find-all session added two days
  ago, for the same reason it was added: it does NOT set `cursorMoved`,
  so the restored scroll survives the next Render.

`matchTrailingNewline` is small and earns its comment: `sort`, `jq`,
`tr`, `fmt` all terminate their last line, while a selection dragged
across three lines usually doesn't. Without the rule, "sort the
selection" grows a blank line every time it runs. Exactly one newline is
stripped, so a command that genuinely wants a trailing blank can emit
two.

### Precedence: git < plugin < LSP

There is one gutter cell, so the ordering had to be argued rather than
picked. A plugin mark **outranks** the git change bar because the user
installed it deliberately and the bar is ambient on every line they
touch; it **loses** to gopls because a compile error is the more urgent
thing to say. Registered between the two in `openFile`.

The glyph is `◆`, deliberately not the LSP's `●` — when both have
something to say about a file, telling them apart at a glance is the
point. Severity is carried by color, from the theme's existing
`DiagError`/`DiagWarning`/`DiagInfo`, so no theme needed a new key.

Marks are keyed by `(file, provider)`, so a re-run replaces its own and
nobody else's — that's what lets three providers watch one file. An
**empty** result still replaces: that's how findings disappear once the
user fixes them.

### Esc-x: the first dynamic prefix

`CLAUDE.md` sets a high bar for a second leader namespace ("a chord is a
real cost, paid by everyone who has to remember which letters are
prefixes"). Esc-x clears it **from the opposite direction to Esc-a**:
that one exists because a fixed surface outgrew the flat table; this one
because plugin keys are **unbounded and belong to the user**. Every
letter they took would be one ced could no longer bind, and any letter
ced later bound would silently break somebody's plugin. A namespace is
the only place a user-owned key can live without fighting the editor's.

It's also the codebase's only *dynamic* prefix. `leaderBinding` grew
`subFor` / `hintFor` / `name`; the table is resolved on every arm, not
cached, because one baked at startup goes stale exactly when the user is
iterating on a manifest.

Three things it had to get right:

- **An empty namespace arms NOTHING.** On the overwhelmingly common
  plugin-free machine, arming would mean `Esc x` swallows the next
  keystroke. It flashes the hint and disarms instead.
- **The miss message names its namespace.** The old string was a
  hardcoded `"No AI action bound to…"`; with two namespaces that lies.
  `leaderChordName` is stamped at arm time and `chordPrefixFor` finds
  the prefix to press again.
- **tmux comes free**, as ever, because both entry paths funnel through
  `fireLeader` — pinned by `TestPluginChord_TmuxAltPath`.

Leader collisions between plugins are **first-declared-wins** over the
name-sorted inventory (stable, so installing an unrelated plugin can't
steal a key you have muscle memory for), and the loser is named in the
≡ Plugins report as `[esc x s taken — unbound]`.

### The kill switch means off, everywhere

`"plugins"` in config.json, default on, ≡ toggle. Honoured at **every**
surface — menu group, palette, leader table, event hooks, and the
decoration source — not just at load. Turning it off drops the painted
marks and stops the edit timer. "Off" that only meant "nothing new
starts" would be a lie on the one feature where the thing running is an
arbitrary shell command.

Nothing runs at startup either: `New` reads manifests, and the first
command fires on a file open, a save, or a deliberate pick. Same promise
MCP makes about not spawning three node processes while you weren't
looking.

### The edit event

Debounced at **800ms** — longer than the LSP's 300ms didChange, because
this spawns a *process*, and a linter restarted every third keystroke is
a space heater. Signature is the summed `EditRev` across tabs, the same
cheap trick auto-save uses.

Armed **only while something listens** (`pluginsWantEdit`). The loop is
event-driven, so a standing timer would wake a resting editor forever —
the constraint the caret blink is built around. An editor with three
save-only plugins never arms it.

### Scoped to the user, deliberately

There is no `<project>/.ced/plugins`, and that's a decision, not an
omission: a checked-out repo that could run shell on open is a
supply-chain hole. The honest version of that feature is `format.json`'s
hash-pinned trust store (`LoadTrust` / `CheckTrust`), and half-building
it would be worse than not having it. `CLAUDE.md` records that as the
gate any future project plugins go through — not on their own.

### Verified in the real binary, not only in tests

Via the `run-ced` PTY capture skill, driving the shipped sample:

```
   3  func alpha() {}
   4 ◆// TODO: rework alpha
   5  func zebra() {}
   6 ◆// FIXME: zebra is wrong
```

`Esc x` → `Plugins  s todo-scan: Sort selection · c todo-scan: Count
TODOs in file`, and `Esc x c` → `Count TODOs in file: 1`. Both ≡ groups
render, with `esc x s` / `esc x c` in the accelerator column.

That needed one addition to the capture tool: it creates its own
throwaway `XDG_CONFIG_HOME`, so a plugin couldn't be demonstrated at
all. `-seed <dir>` copies a directory into it before launch — useful for
`themes/` and `mcp.json` too. (Also documented there: `run` sets the
child's cwd to `-dir`, so `-bin ./bin/ced` resolves against the project
being opened. Pass an absolute path whenever `-dir` isn't the repo.)

### Test discipline

`newTestApp` pins `pluginsDirFn`, `pluginConfigPathFn`, and
`pluginShell` — the first two at temp dirs, the third at a stub that
refuses. This matters more than anywhere else in that harness, because a
plugin **is** an arbitrary shell command and open/save fire hooks by
themselves. `TestRunPluginShell_RealShell` is the single exception and
is restricted to `cat`/`echo`, the same restraint
`TestTermRealGrshIntegration` keeps.

The end-to-end tests drive real events through `pumpAppEvents` with a
recording fake shell, so the capture/apply wiring is exercised without a
process starting.

Menu geometry pins moved: 2 top-zone rows + **83** group actions + **13**
headers (98), height 104, dividers `[2, 5, 101]`. The `CLAUDE.md` copy of
those numbers was already two behind reality and is now current.
