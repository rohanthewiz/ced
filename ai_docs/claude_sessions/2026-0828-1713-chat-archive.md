## What was asked

> I need a way to clear the current chat and perhaps save and be able to
> select the last few chats

One sentence, two verbs, and the "perhaps" is the interesting half: the
panel had become a single unbounded transcript that only ever grew — with
the model's own context growing beside it — and no way to put a finished
conversation down without losing it.

## What shipped

One feature, two surfaces, a new store package.

### `internal/chatstore` — one JSON file per conversation

```go
Save(dir, Conversation) error   // temp-file + rename, then prune
List(dir) ([]Meta, error)       // newest first
Load(dir, id) (Conversation, error)
Remove(dir, id) error
MaxConversations = 30
```

Lives at `~/.config/ced/chats/<id>.json`. Stateless — every function
takes the directory, so the app layer points it at a temp dir in tests
without a global.

### `internal/app/chatarchive.go` — the two verbs

**New chat** (`≡ → Copilot → New chat`, `Esc a x`): archive, empty the
panel, tear the ACP connection down so the next turn opens a fresh
`session/new`.

**Recent chats** (`≡ → Copilot → Recent chats…`, `Esc a r`): the archive
as a fuzzy picker.

```
┌──────────────────────────────────────────────────────────┐
│ Recent chats                                         esc │
├──────────────────────────────────────────────────────────┤
│                                                        1 │
│ Aug 27     why does the caret drift left?  · 2 msgs      │
└──────────────────────────────────────────────────────────┘
```

Restoring paints the transcript and then says what it is:

```
 ❯ why does the caret drift left?

 caretGoalCol holds the widest caret's column;
 using Cursor.Col instead lets a short line pull
 the column left permanently.
                                         ⧉ copy

 — restored transcript from Aug 27 04:22 —
 This is the saved conversation, not a resumed
 session: the agent has no memory of it. Quote
 what matters, or re-attach the files, before
 asking a follow-up.
```

## The decisions worth keeping

**1. CLEARING RESETS THE AGENT, NOT JUST THE SCREEN.** This is the whole
feature. A clear that emptied the panel while the ACP session kept every
prior turn would be a lie in the direction that costs money: the next
question is still answered against a conversation the user can no longer
see, and still billed for it. So `chatNewChat` archives, empties, and
calls `chatRestartSession` — deliberately the agent switch's own
teardown-and-restart, one honest path already tested, rather than a
second "reset" verb reaching into `chatInitialize` to re-issue
`session/new` by itself.

`chatRestartSession` is a no-op while detached and **never clears the
`dead` verdict**: reconnecting is a side effect here, not the user asking
to retry a crashed agent, and quietly borrowing that gesture would turn
"new chat" into a spawn attempt on a machine with no binary.

**2. Nothing is destroyed, which is why neither verb confirms.** Clearing
archives first; opening a saved conversation archives the live one on its
way past. Every gesture is reversible from the same picker, and a
confirmation in front of a reversible action trains people to dismiss
dialogs. Both verbs DO refuse mid-turn — the agent is mid-sentence and
the user is watching it arrive.

**3. Saved after EVERY TURN, not only at teardown.** `handleChatTurnDone`
saves on the success path *and* the error path; `chatShutdown` catches
what was appended after the last turn and the plain-exit case. The
transcript is the one thing in the panel that cannot be reconstructed,
and the write is one small file where the turn already cost seconds of
model time. Same split `session.go` makes by recording a folder VISIT at
startup: a run that dies must cost as little as possible of what actually
happened. The save is **silent on failure** — bookkeeping nobody asked
for, and the failure surfaces where it means something, in a picker that
lists nothing.

**4. One conversation is one file.** `archiveID` is minted on the first
save and reused for every later one, so a hundred-turn chat is one row,
not a hundred. A restored conversation continues **its own** entry for
the same reason: two rows differing only by where the user stopped
reading is exactly the list nobody can navigate.

**5. A RESTORED CONVERSATION IS A READING SURFACE, NOT A RESUMED ONE,
AND THE PANEL SAYS SO.** ced archives the transcript it drew; the agent's
memory lived in a session that died with its process. ACP's
`session/load` was considered and rejected: it is optional, agent-side,
and replays the entire history back as `session/update` notifications,
which would double every message against the transcript ced just
restored. So restoring loads text, starts a fresh session, and writes an
info line naming the gap. Silence there is the worst outcome — the gap is
invisible until a follow-up gets a confidently unrelated answer three
messages later.

**6. Reading needs no agent.** `chatOpenPanel`'s tail was split out as
`chatRevealPanel`, and the restore calls that. The two callers ask
different questions: `chatOpenPanel` means "I want to talk to the agent"
and refuses (loudly) when there is nobody to talk to — which would hide
the archive on exactly the machine where it is all that survives of the
conversation. The start is still attempted, silently, so a follow-up has
somewhere to go.

**7. A clear keeps the prompt history and the pending attachments.**
Up-arrow recall is a typing convenience that spans conversations the way
a shell's history spans directories, and an attachment describes the
message the user has not sent yet — `chatDisconnect`'s own argument. The
selection goes, because its row numbers are about to mean nothing.

**8. A promptless panel is not a conversation** (`chatArchiveWorth`). One
that opened, printed "starting Copilot chat", and closed would otherwise
fill the Recent list with rows nobody can tell apart or remember making.

**9. The archive is USER-scoped, and a row names the project only when it
isn't this one.** A conversation is reached for by what was ASKED ("what
did I work out about the caret blink?"), which does not always live in
the folder you are standing in — and a marker repeating the current
project on every row spends width the TITLE needs while distinguishing
nothing (the status bar's empty-directory rule).

**10. A directory of documents, not a key in `state.json`** — the inverse
of why state.json is separate from config.json. A transcript is far
bigger than anything else ced persists, so folding it in would make every
folder switch's rewrite proportional to how much the user has chatted,
and one bad write would cost the tab list too. One file per conversation
also makes the retention cap a trim of old FILES, and `rm` a working
delete.

## Two bugs the real binary caught

Both found by driving `.claude/skills/run-ced`'s PTY capture against a
seeded `chats/` directory. Neither was reachable from the test suite as
it stood.

**The blank panel.** `chatMaxScroll` is derived from the strip's WIDTH —
how many rows the transcript wraps to — and a closed panel has none
(`chatStripW` returns 0 → `chatRowWidth` returns 1). Pinning the scroll
before revealing the panel wrapped every message to one rune per row and
put the offset at **159** for a two-message conversation, so the restore
opened as an empty strip with nothing on screen to say why. Fix is the
ordering: reveal, then pin. `TestChatOpenArchivedLeavesTheTranscriptOnScreen`
fails with the old order (`scroll = 159, want 0`) and passes with the new
one — verified both ways.

**The id collision.** `chatstore.NewID` used a millisecond tail. Clearing
a chat saves the old conversation and mints the new one's id
*microseconds* later, so the two collided and the second silently
overwrote the first's file — precisely the case the doc comment claimed
to cover. Now the full nanosecond field; sub-nanosecond spacing is not
reachable because a file write happens between the two calls.

A third, smaller one: the picker's project marker compared the stored
root against `session.Normalize(a.rootDir)` but not the other way, so on
macOS every row was tagged with the project it was already in (`/var` vs
`/private/var`). Both sides normalize now.

## Notes for next time

- **`-seed <dir>` is how you photograph anything beside config.json.**
  A hand-written `chats/20260827-091500-000000000.json` in the seed
  directory put a real row in the picker without an agent anywhere near
  the machine — the same trick the plugins inventory uses.
- **Watch the rebuild in a `&&` chain.** A `make build >/dev/null 2>&1 &&
  /tmp/capture …` one-liner ran the capture against a stale binary and
  cost a round trip chasing a bug that was already fixed. `go build -o
  ./bin/ced .` on its own line, then capture.
- The menu geometry pins moved to **144 rows / height 150 / dividers
  `[2, 5, 147]`** (custom-actions height 153). Anything adding a ≡ row
  updates those four numbers.
- **No delete row in the picker**, deliberately: the retention cap and
  `rm` cover it, and it wasn't asked for. `chatstore.Remove` is there if
  it is ever wanted.
- If a future agent advertises `loadSession` and the replay problem is
  solved, the archive already stores everything a real resume would need
  except the agent's session id — which was left out on purpose, since it
  is invalid by the time anybody could use it.
