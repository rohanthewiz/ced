## What was asked

> There is something wrong with CEd's installation as a plugin. Now CEd is
> more of a Cats tool rather than an agent. On the AGENTS section it should
> listed just like the "cats-todo" plugin.

## What was actually wrong — two causes, not one

1. **ced was never a plugin at all.** There was no `cats-plugin.toml` in the
   repo, so `catctl plugin install` / `link` had nothing to read, and
   `catctl plugin list` showed only `rohanthewiz.cats-todo` and
   `rohanthewiz.gonotes` (`~/.config/cats/plugins/` held exactly those two).
   A plugin row in the sidebar is keyed on `PaneState.PluginID`, which is the
   `CATS_PLUGIN_ID` that `catctl plugin run` puts in the spawn env — no
   manifest, no launch, no id, no row.

2. **Even launched as a plugin, ced would still have been an AGENT row.**
   ced's hook reporter (`internal/cats/hooks.go`, source `"ced"`, agent
   `"ced"`) gives the pane hook authority, so `paneRuntime.effectiveAgent()`
   returns `"ced"`. cats' `agentsMsg` (cmd/catway/catway.go) had one rule:
   non-empty effective agent → agent row, and "a plugin that runs an agent
   is reported as the agent". So a manifest alone would not have moved it.

### Why "just stop reporting" was the wrong fix

The agent label is load-bearing in cats for things that are not about being
a coding agent:

- **pane.open_file** — `Dispatcher.findEditorPane` (internal/app/commands.go)
  matches `PaneMeta.Agent` against `editor.agents` (default `["ced"]`).
  `PaneMeta` reads `effectiveAgent`. Drop the report → clicking a path in
  cats spawns a new editor instead of reaching the running one.
- **Notifications / push** — `publishAgent` turns state transitions
  (blocked → attention) into toasts and phone pushes.
- Workspace clean/park (`PaneActivity`) and the ledger also read it.

So the fix is a CLASSIFICATION change in the one roster, not a change to
what ced reports.

## The change

### ced (this repo)

- **`cats-plugin.toml`** (new), written against cats-todo's reference
  manifest:
  - `id = "rohanthewiz.ced"`, `name = "ced"`, `version = "0.3.0"`,
    `platforms = ["linux", "macos"]` (grsh is POSIX-only).
  - `[[build]]` → `sh -c "mkdir -p bin && go build -o bin/ced ."` — `/bin/`
    is already gitignored, so a linked checkout stays clean.
  - One `[[actions]]`: `id = "edit"`, `title = "ced — this project"`,
    `command = ["./bin/ced"]`. No argument: bare `ced` roots at the tab's
    cwd, which is the directory `plugin run` was invoked from.
  - **Deliberately no `bin = [...]`.** That symlinks into `~/.cats/bin`,
    which would shadow a Homebrew / install.sh `ced` on PATH — and cats'
    `editor.command` spawn resolves `ced` through PATH, so installing the
    plugin would silently swap which ced every clicked path opens in.
  - The header comment records the "tool, not agent" reasoning and that the
    version is informational (release CI bumps `internal/version` only).
- **README.md** — new `### Inside cats (as a plugin)` under Install.
- **Linked locally**: `catctl plugin link .` → `linked rohanthewiz.ced
  v0.3.0 → ~/projs/go/ced`; build produced `bin/ced`; `catctl plugin list`
  now shows it with `action edit`.

### cats (`~/projs/go/cats`) — NOT committed this session

- **`cmd/catway/catway.go` `agentsMsg`** — reads `o.EditorConfig()` once;
  a pane whose effective agent satisfies `IsEditorAgent` goes down the
  plugin branch. Plugin id = `panePlugin(tab, id)` when the plugin host
  launched it, else the agent label, so a ced typed into a shell is still a
  row. Exited panes stay out (same corpse rule). Doc comment gained a
  "THE EDITOR IS THE EXCEPTION" paragraph.
- **`wire/down.go`** — `PluginPane.Plugin` comment notes the editor
  fallback id.
- **`cmd/catway/pluginpane_test.go`** — `TestAgentsRollupListsEditorsAsTools`:
  a plugin-launched ced (hook state `blocked`) and a shell-launched ced both
  land in `Plugins` (`"ced"` sorts before `"rohanthewiz.ced"`), a `claude`
  pane stays the only `Items` row, `PaneMeta` still reports
  `Agent="ced"/AgentState="blocked"`, and with `editor.agents` empty every
  reporting pane is an agent again. The test sets `o.cfg = config.Default()`
  because `newOrch` leaves cfg zero — which is also why the existing rollup
  test was unaffected.

The sidebar JS needed nothing: `pluginShort` returns an id with no dot
unchanged, so both ids render as "ced", and the row title is the pane's OSC
2 title, which ced already sets (hostident.go).
