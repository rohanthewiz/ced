## 2. What landed

**Line bookmarks, project-wide.**

- **`internal/editor/bookmark.go`** (new): `Tab` keeps its bookmarks
  (`Bookmark{Line, Text}`, sorted, unique) and follows them through
  edits.
  - **Re-derived from content, not shifted by hooks.** `Buffer.Lines`
    is exported and rewritten wholesale by undo/redo, MoveLines,
    DuplicateLines, Reload/ReloadAsEdit — a per-primitive shift hook
    would miss one. Instead the tab snapshots the lines (a COPY of the
    string headers — MoveLines and single-line InsertString rewrite the
    backing array in place) and, when `EditRev` moved, diffs common
    prefix / suffix: above the region untouched, below shifted by the
    line delta, inside looked up by text nearest the old line, else
    kept clamped.
  - **Twin-line ambiguity**: deleting the first of `b b` reads as
    deleting the second; on a NET deletion a bookmark whose text is the
    line just outside the region lands there. Restricted to net
    deletions so typing on a blank bookmarked line never hops to the
    blank above.
  - `SetBookmarks` (restore) re-anchors by text across the whole file;
    blank text is never searched for.
  - Gutter: the line NUMBER in Accent + bold, `⚑` in its blank leading
    cell (lines < 10000). Not the mark cell — a diagnostic dot would
    hide it.
- **`internal/app/bookmarks.go`** (new):
  - **Two homes, never both**: an open tab owns its bookmarks;
    `closeTab` parks them by path (`a.bookmarks`), `wireTab` adopts
    them back (re-anchored). `allBookmarks` is the union, sorted by
    path then line.
  - **Doors**: ≡ Nav rows Toggle bookmark · Next bookmark · Previous
    bookmark · Bookmarks… (picker with line text, then Clear in
    <file> / Clear all, which confirms). Editor right-click row "Add /
    Remove bookmark". DOUBLE-click on a line number (own
    `bookmarkClick` record so editorPress doesn't read the first press
    as a word-select double-click; checked before `diagGutterPress`).
    No leader (rule).
  - Next/Prev wrap, open parked files, record nav history, skip files
    missing from disk (kept — a branch switch brings them back); the
    picker labels a missing one and removes it on pick.
  - Untitled tabs refuse; cap refused with a flash; rename hooks re-key
    parked paths (file and folder) in `fileops.go`.
- **`internal/history/bookmarks.go`** (new): persistence in
  `.ced/history.bytdb`, table `bookmarks(path PK, marks JSON)`.
  - ONE ROW PER FILE: a bookmark's line is no stable key.
  - STATE, not deltas: `writeHistory` hands over the whole set
    (`SetBookmarks`); only files whose set differs from the loaded /
    last-written one are upserted or deleted. Unchanged files are never
    written, so two instances keep each other's; same file = last
    writer wins. A history never handed a set deletes nothing.
  - Written through on every change (`saveBookmarks` → `writeHistory`)
    and at Close. Loaded regardless of the `"session"` toggle; gated by
    `history.Persists` like the rest. The ≡ row carries "(not saved)".
  - `MaxBookmarks` 500, `MaxBookmarkText` 160 bytes (longer lines
    stored without text) — keeps the table ~100KB worst case, under
    `compactAbove`.

## 4. Decisions and findings

- **First cut stored bookmarks in state.json** (works outside git repos);
  the user prefers `.ced/history.bytdb` — everything worth bookmarking
  is a repo. The state.json field was backed out before commit.
- **Content diff over edit hooks** — see §2; the file header in
  `editor/bookmark.go` has the full argument and diagram.
- **`⚑` width**: uniseg reports 1 (tcell's measure); unverified in a
  real terminal font (N-044).
