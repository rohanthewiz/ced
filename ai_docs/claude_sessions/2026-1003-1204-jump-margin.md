# Session: jump-margin

Session ID: 3bb58a00-2321-491f-8764-59ec4fff65bd
Date: 2026-10-03

Follows `2026-1001-0055-bookmark-labels`.

## 1. The ask

From the cats-todo backlog:

> Sometimes the identifier found ends up at the bottom of the page. Let's
> give it a few lines of buffer when at the very top or bottom

## 2. Diagnosis

Every cursor write sets `Tab.cursorMoved`; Render then calls
`EnsureVisible`, which scrolls MINIMALLY. That is right for a caret
walking line by line, but a JUMP to a line below the view parks it on
the last row (and one above the view on the first row). The verbs that
already used `CenterOnCursor` (goto, find-all peek, project search,
symbols, problems) only centered OFF-screen landings, so an on-screen
hit in the top/bottom row stayed there too. The find bar
(`FocusCurrentMatch`) and `lspJumpTo` (go to definition, etc.) never
centered at all.

## 3. What was done

### editor/jumpmargin.go (new) + jumpmargin_test.go

- `const JumpMargin = 5`.
- `Tab.MarkJump()` sets `cursorMoved` and a new one-shot
  `Tab.jumpReveal` flag.
- `Tab.EnsureVisibleMargin(viewW, viewH, margin)`: EnsureVisible, then
  the least extra scroll that leaves `margin` rows above and below the
  caret's row.
  - `jumpMarginFor` caps the margin at viewH/4 (small panes).
  - Bottom margin counts only lines that EXIST — a hit on the last line
    stays on the bottom row, never scrolls into blank overscroll. Top is
    limited by ScrollY 0.
  - `marginWrapped` does the same in display rows for soft-wrapped tabs
    (ScrollY still a line index, so whole lines at a time).
- Header comment carries the rationale + a before/after diagram.

### editor/tab.go, editor/find.go

- `jumpReveal bool` field next to `cursorMoved`.
- Render: `if cursorMoved { jumpReveal ? EnsureVisibleMargin :
  EnsureVisible }`, then clears `jumpReveal` unconditionally.
- `RestoreView` and `CenterOnCursor` clear `jumpReveal` too.
- `FocusCurrentMatch` calls `MarkJump()` (find bar Enter/Shift-Enter and
  live typing in the bar).

### app wiring (MarkJump after MoveCursorTo)

`lspJumpTo` (definition, implementation, type def, workspace symbols,
validate's jump), `nav.go` retrace (Back/Forward), `goToLine` (also
bookmarks Next/Prev and terminal locations), `findall.go` peek,
`projectsearch.go`, `problems.go`, `lspsymbols.go`. Where the code then
centers an off-screen landing, CenterOnCursor clears the mark; an
on-screen edge-row landing gets nudged by the margin.

Plain motion / clicks are untouched (a click on the last row must not
scroll the text from under the pointer).

### Tests

- `internal/editor/jumpmargin_test.go`: below-view jump, plain move stays
  minimal, on-screen top/bottom edge nudge, comfortable hit untouched,
  file edges (top, last line, near end), small pane scaling, find hit,
  one-shot clearing, wrapped row counting.
- `internal/app/lsp_test.go` `TestDefinitionJumpLandsWithContext`:
  confirmed FAILING without the `lspJumpTo` MarkJump (0 rows below) and
  passing with it (5).
- `make test` (race) all green.

## 4. Observed along the way

`Tab.MaxScroll` is line-indexed even for soft-wrapped tabs; a wrapped
file with few long lines can clamp ScrollY back so the caret is off
screen. The wrapped test was sized (40 lines) to avoid it. Raised as
N-045.
