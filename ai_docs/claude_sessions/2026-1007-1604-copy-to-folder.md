# Session 2026-10-07 16:04 — Copy to… (copy files and folders anywhere)

Session ID: `62007c9a-0fab-4375-90a0-08bab70db1e0`

## Request

From the cats-todo backlog: "I need to be able to copy folder and file
contents to another loc".

## What existed

`copypaste.go` already had a file clipboard: Copy (tree row, ≡ File, Cmd+C,
the tree-marks picker) and Paste. But Paste can only land in a folder the
tree can point at — the clicked tree folder or the active folder — so nothing
could be copied OUTSIDE the open project.

## What was built

**Copy to…** (`internal/app/copyto.go`): copy a file, a folder, or the tree
selection into a TYPED folder anywhere on disk.

- Doors: tree right-click "Copy to…" (on the root too — a project can be
  copied out), ≡ File "Copy file to…" (active tab) and "Copy folder (sub/)
  to…" ("Copy project folder to…" with no active subfolder), and the
  Selected items picker "Copy N items to…".
- Prompt: `openSearchPrompt` titled "Copy <name> to folder", hint
  "absolute, ~/path, or root-relative" (short enough for the "↑ recent"
  tip). Relative paths resolve against the tree root (absolute), `~`
  expanded.
- Destination is always a FOLDER: an existing file is refused (no "copy as");
  a missing folder is created only after a Yes/No confirm naming it on its
  own line; refusals (folder into itself, all sources gone) run BEFORE that
  confirm.
- Recall: new history kind `history.CopyDestinations` ("copyto"), recorded
  in display form when a copy runs; the field is seeded with the last
  destination (else the source's folder); ▾ / Up lists them
  (`histNoun` → "destinations").
- Receipt names the destination and any renamed copy:
  "Copied pkg/ to ~/backup", "Copied main.go to ~/x as main copy.go",
  "Copied 3 items to …"; partial failure says how many landed.

**Shared engine refactor** (`copypaste.go`): `startPaste`'s inline plan and
goroutine became `planCopyInto` → `runCopyPlan` → `pasteDoneEvent` (new
`into` / `src` / `buffered` fields; `into` routes to `handleCopyToDone`).
Paste's messages unchanged.

- Folder-into-itself guard now also checks symlink-resolved paths on both
  sides (`copyIntoOwnSubtree` + `resolveExisting`, which resolves the
  existing prefix of a not-yet-created destination).
- Unsaved buffers: `dirtyBufferOverlay` snapshots dirty tabs at/under the
  sources via new `editor.Tab.EncodedBytes()` (BOM + line ending, no write);
  `copyTreeWith` writes those bytes instead of disk (mode still from disk).
  Applies to Paste too — it used to paste the stale disk copy, against the
  buffer-before-disk house rule. The original tab is NOT saved and stays
  dirty; the flash adds "(with unsaved edits)".

## Real-binary check (run-ced)

In a scratch non-repo project: right-click `pkg/` → "Copy to…" → typed an
outside folder → `pkg/one.go` and `pkg/deep/x.md` landed, status bar
"Copied pkg/ to …". Enter on the seeded field duplicated beside the source
as `pkg copy/`. A missing destination showed the confirm; Esc created
nothing. Two fixes came out of it: the receipt now writes folders with a
trailing `/` like the title, and the confirm puts the path on its own line
(a long path had elided away "does not exist").
