## 1. "+ New branch…" row

- `gitcmd.go`: `menuGitSwitchBranch` now prepends a row labelled
  `newBranchRowLabel` ("+ New branch…") whose `run` is
  `(*App).menuGitNewBranch`. `paletteModal.runSelected` closes the
  picker before running a row, so the prompt opens in a free modal slot
  — no extra plumbing needed.
- Because that row is always present, the picker always opens; the
  `len(items) == 0` → "No other branches" flash is gone. A one-branch
  repo (or a failed branch listing) gets a picker holding only the
  create row. `loadGitBranches`' doc comment updated to match.
- Placed FIRST (as the item asked) so it is a fixed anchor of the
  unfiltered list. Consequence: it is the initial highlight, so Enter on
  an unfiltered list now opens the New branch prompt instead of
  switching to the first branch. Typing filters it out like any row.
  Offered to move it last if that proves annoying.
- Both doors get it for free: ≡ Git "Switch branch" and the status bar
  branch segment (`statusbar.go`) call the same verb.
