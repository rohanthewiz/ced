# Regex search for every text-find action

Session: `1d14ebbd-a217-4d72-82a3-fd2f41ee9584`

## Ask

"Add regex search opt to all find (text) actions. No need to add to find
files options." Then `/sw` (session doc, commit all, push).

## What shipped

A third search modifier, `FindOptions.Regex`, next to match case and whole
word. It reaches every TEXT find: the find bar (find + replace), Find all in
file, Find in project, Find all in folder. The file finder is untouched.

### Engine — `editor.Matcher` (internal/editor/find.go)

One compiled query object behind every scan, staleness check and
replacement, so the literal and regex paths can't drift per caller:

```
query + FindOptions ──NewMatcher──► *Matcher ──┬─ All / Line   (scan)
                          │                    ├─ At           (still a hit?)
                          └─ error (bad regex) └─ Expand       ($1 replacement)
```

- RE2, matched per LINE (the buffer is []string; `\n` finds nothing — the
  same within-a-line contract the literal search had).
- Case-insensitive = `(?i)` prefix (never lowercase the pattern — it would
  corrupt `\S`). Whole word = the SAME `wordBounded` post-filter as literal
  mode, not RE2's ASCII-only `\b` (would disagree on "café").
- Byte offsets → rune columns incrementally per line.
- Zero-width hits DROPPED (`^`, `x*`): nothing to paint, invisible "1 of N"
  stops, insert-everywhere Replace all.
- `FindAllOpts` / `MatchesAt` are now thin wrappers. **`MatchesAt` gained a
  `width` parameter** — regex hits vary in width, so "still a hit" must
  check (col, width), and regex mode re-scans the whole line (context:
  `^`, leftmost-first) to agree with `All` exactly.
- `FindQueryError` strips "error parsing regexp:" → e.g. "missing closing )".
- nil `*Matcher` (empty query) is valid and matches nothing.

### Replace (internal/editor/replace.go, app/findall.go)

Under regex the replacement is a TEMPLATE (`$1`, `${name}`, `$$`) expanded
per hit by `Matcher.Expand`, BEFORE any edit lands (ReplaceCurrent expands
against the hit it overwrites; ReplaceAll and the list's `buildReplacePlan`
expand against the untouched buffer, then the bottom-up pass applies them).
Literal mode keeps `$1` as text. The list's "replacement is the search text"
refusal is literal-only.

### Project search (internal/search/search.go)

Compiles ONE Matcher per walk, shared by all 8 workers (`*regexp.Regexp` is
concurrency-safe). `searchFile` now takes the Matcher. Bad pattern → nothing;
the app validates first.

### UI (internal/app)

- Find bar: `.*` button, rightmost (order Aa |W| .*, VS Code's), `Alt+r`;
  `findRegexRect` chains `findWordRect` → `findCaseRect` so Aa stays the
  leftmost edge the field stops at. Button tip mentions `$1, ${name}`.
- Bad pattern in the bar: counter reads `regex: missing closing )` in the
  no-match red, not "no results".
- ≡ Find row "Regex: on/off" (`menuToggleFindRegex`) → menu pins bumped
  (200 rows, height 206, dividers `[2, 5, 203]`; CLAUDE.md updated).
- `openFindPrompt` (find.go): the three text-find prompts get a
  `[regex: off]` chip (alt+r) flipping the App's own toggle (prompts own
  the keyboard — the keyboard-owning-surface rule). Hint suffix
  " · alt+r regex", kept short so "↑ recent" still fits.
- `findLiteral`: POINTED-AT seeds (selection, caret word) are QuoteMeta'd
  under regex; typed queries never are. Toggling never rewrites the query.
- `showFindAll` / `startFolderSearch` flash "bad regex …" BEFORE searching.
- Find-all list caches its Matcher (`matcher()`, keyed on query+opts) —
  `rowStale` runs per visible row per frame. Regex lists open the filter
  box EMPTY (`findAllFilterSeed`): the box is a substring filter.
- `findOptionsNote` adds "regex" to titles/flashes.
