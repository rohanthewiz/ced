# N-131: undo entries are deltas, not buffer copies

Session: `668a363f-1215-49d2-90d9-6dd805eefd50`

## Ask

Load the last session (`/sl`), then "Next list item N-131": undo depth
collapses on big files and depends on where you edit; fix with delta undo
records so memory and accounting are O(change), `pushUndoEntry` staying
the single write path. Then this wrap.

## The problem, measured first

A throwaway probe (400 structural edits) on the old code: 6k lines kept 71
steps at the top / 335 at the end; 50k lines 8 / 41; 200k lines 2 / 10.
Two causes: every entry was a full `[]string` header copy (16 bytes ×
lines) charged to the 32MB budget, and `snapshotCost` compared index by
index, so an insert near the top charged every shifted line's bytes.

## The design

**Mutators unchanged; the delta is diffed out lazily.** Every mutator
already calls `pushUndo` BEFORE editing and then edits any way it likes
(single-line patch, slice rebuild, a whole new Buffer). Rather than
hooking each primitive (the bookmarks' rule: diff content, never add
per-primitive hooks), `pushUndo` now OPENS a step — it records only the
caret — and the next push / Undo / Redo SETTLES it: `lineHunks(undoBase,
buffer)` → an `undoStep`, then `undoBase := buffer`. `undoBase` is ONE
private header copy per tab (the buffer at the last checkpoint), not one
per step.

```
pushUndo   settle the open step, open a new one (caret only)
(edits)    buffer drifts from undoBase
settle     lineHunks(undoBase, buffer) → step; push; undoBase := buffer
```

**`lineHunks`, cheapest first:** prefix/suffix trim (`==` on strings — a
pointer compare for untouched lines); same line count → index-aligned runs
(typing, Replace all, rename, multi-caret typing); one side ≤ 32 lines →
one span (Enter, paste, deleted block); both sides large with a shifted
count → `internal/diff`'s patience differ (multi-caret Enter, formatter
run, resolve-all). Equal counts with more than half "differing" also go to
the differ (a line added at the top and one removed at the bottom). The
differ is the compare panel's own — CLAUDE.md's "never a second
algorithm".

**Cost (`stepCost`)**: hunk headers + fixed overheads + the text only this
entry holds: REMOVED lines on the undo stack, INSERTED lines on the redo
stack (a typing chain shares "ab" between step 1's inserted and step 2's
removed — charging both would halve the history). Re-stamped whenever a
step moves between stacks (`pushUndoEntry` / `pushRedoEntry`).

**Safety:** a change no `pushUndo` announced is filed as its own step and
drops redo; every step is verified (`hunksFit`: line count + every line it
replaces) before it is applied, and a misfit drops the history instead of
writing over the wrong lines. Same-shape hunks patch the buffer in place;
others rebuild once. Hunk slices are always private copies (the buffer and
`undoBase` are patched in place).

**`UndoDepth` counts the open step**, so settling never moves it — the
workspace-edit journal compares depths across such moments. The entry cap
(500) counts it too; trimming keeps the last settled step.
