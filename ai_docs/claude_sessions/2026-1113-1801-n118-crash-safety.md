# N-118: crash safety — panic rescue, SIGHUP/SIGTERM through Close, auto-save cap, tab list on open/close

Session: `6e6a4f1a-17b3-4b52-94a3-f741dddfb42b`

## Ask

"Next list item N-118": no `recover()` and no `os/signal` anywhere, so
a panic (main loop or any goroutine), SIGTERM, or SIGHUP from a killed
tmux pane skipped `Close` — unsaved edits, the tab list and history lost,
and the terminal left in raw mode / alt screen / mouse 1003 / kitty
keyboard. Auto-save was a pure debounce, so steady typing was never
saved. Four parts: (a) recover + goroutine wrapper → rescue dirty
buffers, `Fini`, re-panic; (b) SIGHUP/SIGTERM → quit through `Close`;
(c) a max wait on auto-save; (d) `recordSession` on tab open/close.
Plus a decision: where recovery files live.

**Decision (asked):** `~/.config/ced/recover/` — one home for every
project, no writes into repos. Chosen over `<repo>/.ced/recover/` with
a fallback (two homes) and repo-only (nothing rescued outside a
repository). CLAUDE.md's allowed `~/.config/ced/` entries gained
`recover/`.

## The design

**internal/crash** (new, stdlib only, two files):

- `guard.go` — `Recover()` is deferred FIRST in every goroutine. It
  does not swallow: it captures `debug.Stack()` (while the panicking
  frames are still on the stack) into a `*Panic` and hands it to the
  process-wide `Handler` (`atomic.Pointer`; `SetHandler` returns a
  restore that only uninstalls itself, so an App closing after its
  successor installed a handler can't remove it). No handler → re-panic
  the ORIGINAL value. `Panic.Error()` carries the goroutine's stack, so
  the final crash output shows where it really happened.
- `rescue.go` — `Rescue(dir, root, reason, now, bufs)` writes one
  folder per rescue, `<YYYYMMDD-HHMMSS>-<project>/`: root-relative paths
  for project files (so `diff -r` against the project works),
  `_outside/<abs path>` for others, `untitled-N.txt`; files 0600 with
  O_EXCL + fsync, folders 0700; `Mkdir` claims the folder atomically
  (two instances hung up in the same second get `-2`); every buffer
  attempted, errors joined; `INDEX.txt` last (why, when, root, each
  `rescued <- original`, notes). `Prune` deletes only stamp-named
  folders older than `KeepFor` (14 days), run when the NEXT rescue is
  written — nothing at startup.

**app/crashsafety.go** (new):

- `installCrashSafety` in `New` before any goroutine starts (handler +
  signal watcher); `teardownCrashSafety` LAST in `Close`, so a SIGTERM
  during the terminal restore is still caught rather than killing the
  process mid-`Fini`.
- `recoverRun` (must be the deferred function itself) is deferred by
  `Run`, `New`, `OpenFile` and `RevealPath` (main calls the last two
  between New and Run). `crashRescue` (sync.Once): rescue buffers →
  `recordSession` only if the session record is ARMED (a panic mid
  `restoreSession` must not write half the tab list) → `writeHistory` →
  `Fini` → exit note; each step individually guarded. Then re-panic.
- Goroutine panic → `onGoroutinePanic` (on that goroutine) posts a
  `crashEvent` and sleeps `crashHandoffWait` (3s); the main loop's
  `handleCrashEvent` re-panics it inside Run's recover, so every tab
  read is on the main goroutine. If the loop never takes it (queue full,
  loop wedged — possibly on this goroutine), the goroutine rescues
  itself (a racy read, accepted for a process seconds from death) and
  re-panics via the `goroutineCrash` seam.
- SIGHUP/SIGTERM → watcher posts `signalQuitEvent` (retrying while the
  queue is full) → `quitUnattended`: `flushAutoSaveForExit` (the
  focus-out rule — auto-save on, no modal/menu, `autoSavable` +
  `autoSaveGuard` — but plain `Save`, no format/LSP/diff follow-ups that
  the exit would abandon), rescue whatever is still dirty, clear
  `nextRoot`, `quit`. The normal `Close` runs; it prints the exit note
  after `Fini`. Idempotent (SIGHUP and the tty error both arrive).
- **Found along the way:** tcell's input loop posts ONE
  `*tcell.EventError` when reading the tty fails and then stops reading
  for good — ced ignored it and sat with no input forever. Now
  `handleTTYError` → `quitUnattended`.
- A panic NEVER writes the user's file (the buffer may be what broke);
  a cp1252 buffer the code page can't hold is rescued as UTF-8 with a
  note — a rescue never refuses.

**88 goroutine sites** got `defer crash.Recover()` — inserted by an
AST-driven tool (scratchpad) at each `go func` body, plus the named
targets by hand (`lsp.Client.readLoop`, `cats.Stream.run`,
`cats.Reporter.send`, `remote.Server.accept/serve`, the blame closure).
`TestEveryGoroutineRecovers` (internal/crash) walks all non-test source
and resolves each `go` statement: func literal → first statement must be
the guard; named func/closure → every same-package body under that name
must start with it. It caught the blame closure `run` sharing a name
with another closure → renamed `blamePass`. `time.AfterFunc` callbacks
are NOT covered (one-line PostEvents; documented in the package doc).

**(c) auto-save cap** (autosave.go): `autoSaveDirtySince` = first edit
of the current run; `autoSaveWait(now)` = min(interval, start +
max(30s, interval) − now), floored at 0. The run ends at every save
pass (else a conflicted tab staying dirty would put the cap in the past
and every keystroke would arm a zero wait — a save storm) and whenever
nothing is dirty (checked BEFORE the EditRev signature: a save clears
Dirty without moving EditRev). The modal deferral re-arms with the
PLAIN interval (`armAutoSaveIn`) — a capped zero would spin while the
modal stays open.

**(d) tab list on open/close** (folder.go): `sessionAfterEvent` in the
after-event chain compares the named tabs' paths with the last write
(allocation-free `sessionTabsMatch`) and records on any change — opens,
closes, Save as, reorders — via the shared `sessionEntry` builder.
Quiet (`writeSessionStore`, split out of `updateSessionStore`): the
startup write already flashed any state-file problem. Armed by New
after `restoreSession`; directly built Apps (tests) stay unarmed.
Switches and cursor moves don't write.
